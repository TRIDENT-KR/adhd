프롬프트 추출 검증은 기존 문자열을 추출 **전**에 hash로 고정했습니다. 3개 언어 ×
2개 local time에서 원본 렌더링과 byte 단위로 같은지 검사합니다. validator의 동작
자체는 바꾸지 않습니다. 기존 미커밋 하네스를 복구했다는 주장이 아니며, 확인
가능한 레거시 도구를 새 공식 도구로 대체했습니다.

2026-10-29 후속 통합에서는 기존 로컬 앱·서버 변경을 함께 반영했습니다. 공유
프롬프트의 추가 안전 제약과 validator 변경은 의도적인 동작 변경입니다. 새
프롬프트 snapshot은 저장된 로컬 커밋 `2e1a123`에서 만들었으며, 최초 추출 근거는
그대로 보존합니다. 모델 단독 점수와 앱 전체 품질은 계속 구분합니다.

## 참고할 공개 평가와 점수

| 평가                                                                   | 제공하는 지표/증거                                                                             | Mora에 적용                                                    | 직접 비교할 수 없는 이유                                                |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| [BFCL 공식 리더보드](https://gorilla.cs.berkeley.edu/leaderboard.html) | 함수 호출 정확도, AST 기반 인자 검증, relevance/irrelevance, 다중 호출·여러 턴; 공개 모델 점수 | 함수+인자를 함께 채점하고 불필요한 호출을 별도로 확인          | API·schema·데이터·프롬프트·평가 버전이 다름. 전체 점수는 하위 범주 평균 |
| [MASSIVE 논문](https://arxiv.org/abs/2204.08582)                       | 51개 언어의 의도 분류·slot filling 데이터, 60 intents·55 slot types                            | KO/EN/JA별 route/field 지표와 번역 family 관리                 | 시간 계산·삭제 안전성·Mora 함수 의미는 직접 평가하지 않음               |
| [τ-bench 공식 저장소](https://github.com/sierra-research/tau-bench)    | 최종 상태와 반복 성공률 pass^k                                                                 | 한 번 우연히 맞는 결과와 매번 맞는 결과 분리                   | retail/airline의 대화·도구 실행 환경; Mora의 단발 JSON 평가와 다름      |
| [JEVal 논문 v2](https://arxiv.org/abs/2610.03935v2)                    | 36개 데이터셋·10개 영역·11,257건의 bilingual 결정 평가; 불확실성 및 시스템 합성 분석           | Jev를 붙여도 최종 작업 성공·고신뢰 오답·fallback 결과까지 확인 | Mora KO/EN/JA 데이터가 아니고 같은 시스템 구성이 아님                   |

실제 공개 숫자의 예로 τ-bench 저장소의 **역사적 GPT-4o tool-calling / airline**
결과는 Pass^1 **0.420**, Pass^4 **0.200**입니다. 이는 반복 신뢰성이 단일
성공률과 다를 수 있다는 예시이지 최신 Gemini/Jev/Mora 성능의 예측값이 아닙니다.
원 저장소는 최신 버전을 τ³-bench 저장소로 안내하고 있으므로 버전도 고정해야
합니다. BFCL 페이지의 조회 시 표기 버전은 V4, 업데이트 표기는 2026-04-12, 재현
evaluator는 `bfcl-eval==2025.12.17`입니다. 서로 다른 버전 점수를 섞지 않습니다.

이 조사에서 Mora의 현재 계약·프롬프트·선택할 Gemini ID와 **같은 조건의 공개
점수는 확인하지 못했습니다**. 숫자가 존재한다는 이유로 모델 채택/출시 근거로
옮기지 않습니다. 공개 데이터셋을 이번 세트에 복사하지 않았으므로 외부 데이터
라이선스·오염을 묵시적으로 들여오지도 않았습니다.

[Jev를 분석한 Amplitude의 자체 실험](https://www.amplitude.com/blog/jev-analysis)은
분류 단계가 빠르더라도 잘못된 확신과 후속 호출이 이득을 상쇄할 수 있음을
논의합니다. 이는 그들의 analytics workload 근거이며 Mora 성능 근거는 아닙니다.
따라서 이번 비교 단위는 분류기 단독 응답속도가 아니라 **분류+fallback+최종 함수
결과**입니다.

이름도 분리합니다. [feder-cr/jev](https://github.com/feder-cr/jev)는 README에서
jevos라는 오픈소스 대안으로 소개되며 TypeSafe의 Jev와 같지 않습니다. 외부
run에는 실제 제품·모델·버전과 설정을 남겨야 합니다.

## 선택한 구현

Mora는 이미 Deno TypeScript validator를 보유합니다. 다른 평가 플랫폼을 추가해
JSON 계약을 다시 구현하는 대신 작은 Deno CLI로 실제 validator를 재사용합니다.
LLM 심판은 가격·편향·재현성 문제와 정답 누출을 늘리므로 exact 필드 평가의
기본값으로 두지 않습니다. 문장 표현의 타당성은 사람이 별도로 검수합니다.

각 시나리오의 번역과 반복을 같은 family로 묶고, 모델 비교도 같은 family의 차이를
재표집합니다. 단일 평균뿐 아니라 함수 precision/recall/F1, 인자 오류,
언어·태그·위험도, 불필요한 질문, 위험한 변경 제안을 노출합니다. API 실패와 빠진
결과는 빼지 않습니다.

현재 합성 세트는 회귀 검출에는 유용하지만 독립 실사용 정확도 추정에는
부족합니다. 더 좋은 근거를 얻는 핵심은 평가 프레임워크를 더 많이 붙이는 것이
아니라, 검수된 독립 데이터·정확한 실행 manifest·공정한 비교·실제 앱 QA를
확보하는 것입니다.
